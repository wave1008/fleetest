# 決定の台帳

| 種別 | 範囲 | 読む場面 | 扱わないこと |
|---|---|---|---|
| 正典 | ユーザーが決めた方針・不採用・トレードオフ(DR) | 決定を変えたく/緩めたくなったとき・同じ論点を提案する前 | 決定の実装と仕様(→ 本文の参照元)・事故の経緯(→ [maintainer-notes/](maintainer-notes/README.md)) |

本文(CLAUDE.md・規則ファイル・設計書)は規則だけを書き、決定の理由・根拠・見直す条件はここに置く。本文からは `DR-n` で指す。

**種別**は2つ:

- **方針** —— 優先順位で決めた。実測を測り直しても変わらない。変えるのはユーザーの判断だけ
- **実測** —— 実測を根拠に決めた。「見直す条件」の測定をし直して結果が変われば、見直しを提案してよい

**ここに載せないもの**:

- UI の見た目・文言・配置の好み(理由が「こう見たい」だけのもの)は、本文に `決定: ユーザー <日付>` を添えるだけにする。変えるときはユーザーに確かめる
- 定義から導いた値(例: 量子化1段階未満 = 1.0)は、本文の定数の隣に根拠を書く。決定ではない

**欄の書き方**: 分からない欄は推測で埋めず「未記録」と書く。「見直す条件」は理由から言える範囲だけを書く。
実装や経緯から推した理由は、先頭に「(推測・未確認)」を付けて区別する(ユーザーが確かめたら外す)。

## DR-1 失敗の記録に「環境要因」などの分類を置かない

- 種別: 方針
- 決定: ユーザー(日付未記録)
- 内容: 失敗の記録に置くのは事実(フェーズ・コマンド名・経路・注記)だけ。言えない欄は省き、「その他」に丸めない
- 理由: アプリが重いのか機械が混んでいるのかをツールは区別できず、推測は誤った緑・赤を作る
- 見直す条件: 未記録
- 参照元: CLAUDE.md「失敗の記録と操作の規律」

## DR-2 モニターの配信を止めるのは性能の計測と regress.py の回帰だけ

- 種別: 実測
- 決定: ユーザー(regress.py が自分で止めて戻すのは 2026-11-11)
- 内容: 合否を見るだけの実行では配信を止めない。regress.py は段2の前に全マシンの配信を止め、終わり・中断のどちらでも戻す
- 理由: 配信ありの回帰で、手元の Android が白紙・固まりで赤になり、止めて回し直すと同じシナリオが通った(11/1・11/11)。8台に配信を張ったフル E2E では Android が実際に落ちた
- 根拠: docs/verification/operations.md「モニターと E2E」
- 見直す条件: 配信を張ったままの回帰で、配信が原因の赤が出なくなったと測れたとき
- 参照元: CLAUDE.md「デバイス実行(E2E)」

## DR-3 特定のアプリに特化した直しを採用しない

- 種別: 方針
- 決定: ユーザー 2026-11-13
- 内容: 判定・自動の操作・待ちの条件を、1つのアプリの形(id・ラベルの語・表記・寸法)に合わせて書かない。条件は形の一般的な性質で書き、固定コーパスの全数で直しの前後を突き合わせる
- 理由: 1つのアプリの形に合わせた条件は、別の画面で誤った赤・緑になる(`*円*` を ¥ にも当てた待ち・名前だけでグラバーを引いたシートの救済は、どちらも外した)
- 見直す条件: 未記録
- 参照元: CLAUDE.md「判定の規律」

## DR-4 根拠のない定数を置かない

- 種別: 方針
- 決定: ユーザー(日付未記録)
- 内容: 定数には根拠・単位・尽きたときの発話を書く。書けないなら数字を調整せず、数字への依存を消す
- 理由: 片方の文脈で詰めた値は、別の文脈で遅くなるのではなく黙って誤る
- 根拠: MN-12.1・MN-104.5
- 見直す条件: 未記録
- 参照元: CLAUDE.md「判定の規律」

## DR-5 API の JSON 契約に後方互換の読み替えを置かない

- 種別: 方針
- 決定: ユーザー 2026-09-20
- 内容: 契約を後方非互換に変えたら版を +1 する。欄を足すときも `decodeIfPresent ?? 既定値` で古い形を吸わず、必須にする。欄が無いこと自体が意味を持つ省略可の欄(「測っていない」等)は読み替えに当たらない(DR-75)
- 理由: 互換の経路はテストでしか踏まれずに腐り、沈黙する縮退を作る(decode 失敗で機械1台ぶんの行が消える等)。リモートは毎回 align で同じ中身へ揃える運用なので、版のずれた状態は存在しない
- 見直す条件: リモートを align で揃える運用をやめるとき
- 参照元: CLAUDE.md「版と契約の同期」

## DR-6 FM の失敗トリアージ(分類・要約・修正案)を置かない

- 種別: 実測
- 決定: ユーザー 2026-09-15
- 内容: 失敗の分類・要約・修正案を FM に作らせない。`FMTriageRemovedTests` が再混入を落とす
- 理由: 実レポート 30 件のうち要約 13 件が事実を誤り、分類は環境の問題を `appBug` にし、修正案は別要素への差し替えを勧めた
- 根拠: MN-21
- 見直す条件: MN-21 の測り方で誤りの率を測り直し、下がったと確かめられたとき
- 参照元: CLAUDE.md「判定は1箇所に置く」

## DR-7 FM によるロケータ自己修復(FM ヒール)とヒールキャッシュを置かない

- 種別: 実測
- 決定: ユーザー 2026-09-15
- 内容: 自己修復は指紋照合だけ。`heal` は指紋照合のスイッチで、FM を使わないので FM のトグルと独立。`FMHealRemovedTests` が再混入を落とす
- 理由: 採用門(自己申告 confidence == "high")が日英 272 件で1度も開かず、confidence は正誤と相関しなかった。典型的なドリフト(id だけ変わりラベル不変)は指紋照合が決定的に拾う
- 根拠: MN-22
- 見直す条件: MN-21 の測り方で誤りの率を測り直し、採用門を置ける相関が見つかったとき
- 参照元: CLAUDE.md「判定は1箇所に置く」

- 理由: フリート AVD の userdata-qemu.img.qcow2 が 6〜12GB に肥大した(qcow2 差分は縮まない)。閾値 8GB は、wipe 直後の再構築だけで 2〜4GB になるため 4GB 以下はスラッシングになるから。凍結の真因は `-gpu host`(DS-7)で、Wipe は凍結には無効と確定した
- 根拠: docs/performance-tuning/guide.md の Wipe Data の行(2026-07-17 精査)

- 参照元: docs/performance-tuning/guide.md の Wipe Data の行

# exist, notExist, countIs

[in English](existence_assertion.md)

セレクタで指した要素の存在・不在・件数を検証します。

## 関数

| 関数 | 説明 |
|---|---|
| `exist(selector, requireVisible:, waitSeconds:, scroll:, maxSwipes:)` | 存在検証です。マッチした要素を返すので、text・value・id の検証をチェーンできます。実行プロファイルで `fmTextVisibilityCheck` か `ocrTextVisibilityCheck` が `true` の run では、実際に見えていることも確認します。 |
| `notExist(selector, waitSeconds:, scroll:, maxSwipes:)` | 要素が消えるまで待ちます(初回で不在なら即成功)。`scroll:` を指定すると、その方向へスクロールしながら探し、見つかった時点で不在検証を失敗させます。スクロールしても見つからなければ、通常どおり現在のビューポートでの消滅待ちに進みます。 |
| `countIs(selector, count, waitSeconds:)` | ツリー上の候補件数を検証します。可視性は見ません。`\|\|` は和集合の総数(重複は1度だけ)。ラベルで数えるときは型で絞ってください(例: `.button&&追加` — ボタンと内側のラベルは別要素として両方マッチするため)。 |
| `exist(selector, scroll: .noScroll)` | `withScrollDown` / `withScrollUp` / `withScrollRight` / `withScrollLeft` ブロックの内側でも、現在の画面だけで存在検証します。 |

`waitForDisplay` / `waitForClose` はスクロールせずに要素の表示/消滅を待つコマンドです。
[wait](./wait_ja.md) を参照してください。

## 例

```swift
expectation {
    exist("#welcome_text||Welcome")
    notExist("#loading_spinner")
    countIs("#cart_item", 3)
}
```

## 注意点

- `exist` の戻り値は text・value・id の検証にチェーンできます。
  [テキストの検証](./text_assertion_ja.md)・[値の検証](./value_assertion_ja.md)・
  [idIs](./id_assertion_ja.md) を参照してください。
- `exist` / `notExist` / `countIs` は常にセレクタを取ります。複数の要素を解決しうるコマンドなので、
  直前に取得した要素へ暗黙に効く形はありません。
- **`notExist` は可視性を見ません。** アクセシビリティツリーから消えたかどうかだけで判定します。
  別のモーダルに覆われて見えないだけでツリーに残っている要素は「まだ在る」と扱われ、
  待ち時間が過ぎると失敗します(`exist` / `select` は既定で見えていることまで確かめます)。
- **手前のダイアログが裏を隠している画面で通った「無い」の検証には、注記 `absence-behind-modal` が付きます。** iOS の画面内のモーダル・手前の別ウィンドウや、Android のアプリ自身のダイアログは、その裏の要素をアクセシビリティツリーから外すことがあり、そのとき `notExist` / `countIs(…, 0)` は要素が裏にあっても通ります(フレームワークによっては裏の要素がツリーに残り、上の「まだ在る」の扱いになります)。合否は変えないので、裏の要素について確かめたいときは先にダイアログを閉じてください。注記の文はレポートのステップの行にも出ます。
- **Android では、別のアプリの画面を読んで通った「無い」の検証に注記 `absence-checked-on-another-app` が付きます。** `notExist` / `countIs(…, 0)` が通ったときに前面のアプリがテスト対象のアプリでない(シナリオが起動した別のアプリが前面にある、またはシナリオがテスト対象のアプリを止めた後でランチャーが前面にある)と、その検証はテスト対象のアプリについて何も言っていません。別のアプリを検証するつもりのシナリオもあるので合否は変えません。テスト対象のアプリを指していたなら、先にそのアプリを前面へ戻してください。
- **中身が枠の外へ続くスクロールする一覧の中を `countIs` で数えると、注記 `count-in-scrolling-list` が付きます。**
  画面に見えている行の数は画面の大きさ・向きで変わるので、同じ数え方が別の端末では別の数になります。合否は変わりません。
  画面の大きさに依らないものを数えるか、各項目までスクロールして確かめてください。
- 「実際に見えていること」の確認では、画面に描かれた文字を期待テキストと突き合わせます。
  **先頭だけが描かれている**ときは次のように扱います(テキストの検証・値の検証も同じ)。
  - 末尾に省略記号(`…`)が描かれている → アプリが意図した省略として緑。注記 `text-ellipsized` が付きます
  - 省略記号が無く、描かれたのが期待テキストの半分より多い → 緑。注記 `text-partially-hidden`
    (テキストの一部が隠れています)が付きます
  - 省略記号が無く、描かれたのが半分以下 → 失敗(`most of the text is hidden`)。
    わざと大部分を隠す画面では `requireVisible: false` を使ってください
  - 判定の例(画像つき)は [テキストの可視性検証の判定](../testclass/text_visibility_check_ja.md) を参照してください
- **`exist` のセレクタに一致する要素が複数あるときは、どれか1つの文字が見えていれば緑です。** 最初に一致した要素が見えないと判定されると、残りの一致を順に確かめます(画像の説明文が商品名と同じで、画像のほうが先に一致する画面など)。`[n]` で番号を指定したセレクタと相対セレクタは、その1つだけを確かめます(テキストの検証も同じで、値が期待に合う一致だけを確かめます)。
- **`screen rendering check (…)` という名前のステップが赤になったときは、シナリオの手順の誤りではありません。** iOS Simulator の描画が壊れて、画面に文字が描かれていない(アプリの領域が一色・文字が一つも無い)ことを、スクリーンショットで確かめた結果です。シナリオを書き換えずにもう一度実行し、続けて出るならアプリか Simulator を起動し直してください。詳しくは [画面の描画の検査](../testclass/text_visibility_check_ja.md#画面の描画の検査ios-simulator-のみ) を参照してください。
- **読み込み中に本物と同じ `#id` の骨組みの行を出すアプリでは、`exist` は読み込み前に通ります。** 完了の判定には使わず、`enabledIsTrue()`(骨組みが無効として公開されている場合)か、読み込み済みの件数の echo で確かめます。一瞬で終わる途中の状態(`state=loading` 等)の検証は端末の速さで緑になったり赤になったりします([UI 部品ごとの癖](../writing/ui_component_patterns_ja.md#読み込み中の骨組みスケルトン))。
- **`#id` で指しても、テキストの可視性検証は要素のラベルが画面に描かれているかを見ます。** ラベルが読み上げ用で画面に描かれない要素
  (Android の電卓の空の数式欄の `No formula` など)は失敗します。在ることだけを確かめるなら `exist("#formula", requireVisible: false)` と書きます。
  作成中の MCP の確認は可視性検証をしないので、本番の run で初めて赤になります。

# pressEnter, hideKeyboard

[in English](press_enter_hide_keyboard.md)

キーボードの確定アクションを発火する、またはソフトキーボードを閉じます。

## 関数

| 関数 | 説明 |
|---|---|
| `pressEnter(settle:)` | フォーカス中の入力欄へ Enter/IME アクション(検索・完了・送信・改行など)を発火します。どの欄にも焦点が無いときは、焦点が立つかキーボードが出るまで最大 1.5 秒待ってから Enter を送ります。待っても焦点が立たなければ、iOS ではステップは失敗せず、そのまま Enter を送り、「焦点のある欄が無かった(キーは前に焦点のあった欄へ行った可能性がある)」という注記を付けます。**Android では、入力の焦点を持つ欄が無いとき、または焦点のある欄の入力の接続がすでに閉じているとき(Flutter は Enter の後に接続を閉じます)、Enter を送らずに失敗します**(受け取る欄が無いためです)。欄を `tap` してからもう一度 `pressEnter()` を呼んでください。 |
| `hideKeyboard(settle:)` | ソフトキーボードを閉じます。出ていないときは何もしないので、常に呼んでも安全です。**Android** は戻るキーを撃ちます。**iOS** はキーボードの上の何もない点(どの要素にも載らない点、または操作できない画面幅の容器だけに載る点。文字・画像・ボタン・入力欄・トースト・ステータスバーの上は避けます)をタップし、空きの点が無い(画面いっぱいの Web ページ)か、タップしても閉じないときは、キーボードの上の OS の入力補助バー(Web の入力欄が出す Previous / Next / Done)の Done を押します(アプリ独自のバーは押しません)。それでも閉じなければ Enter を送ります。閉じた後の次の操作(`tap` など)は、画面の情報からキーボードが消えるまで待ってから要素を探します(Android。端末によっては、閉じた後も数秒キーボードが残って見え、画面下端の要素が見つからないため)。 |

## 例

```swift
type("#search_box", "腕時計")
pressEnter()               // 欄の確定アクションを発火

android {
    hideKeyboard()
}
```

## 注意点

- `pressEnter(settle:)` が改行を入れるか確定アクションを発火するかはフィールド側が決めます(コマンド
  側では選べません)。`type` の末尾 `\n` についても同じ話が当てはまります。詳細は
  [type](./type_ja.md) 参照。
- **iOS の `hideKeyboard()`**: 背景のタップで閉じるかはフレームワークで違います。iOS Simulator での実測では、Compose Multiplatform は背景のタップで閉じ、SwiftUI と Flutter は続けて送る Enter で閉じます。どちらでも閉じなければステップは失敗します。React Native は、inapp-boost モード(既定)では、背景をタップする前に、焦点のある入力欄からキーボードを外して閉じます(Enter は送らないので、送信や検索は走りません)。xcuitest モードにはこの外し方が無い(XCUITest ブリッジが断ります)ので、React Native も他のフレームワークと同じ順、つまり背景のタップ、続けて Enter になります。ステップの注記に撃った点が出ます。タップでは閉じず Enter を送ったときは、Enter が欄のリターンキーの動作(検索・送信・次の欄)も発火させることが注記に書かれます。タップの後にキーボードより上の要素が消えていたときは、何も発火していないか確かめるよう注記が促します。
- **キーボードの下にある対象**: `tap` / `type` / `clearInput` が、対象の中心がキーボードの下にあると気付いたときは、まず容器をスクロールし、それでも覆われていれば副作用のない手段(iOS は上の背景タップ(React Native の inapp-boost モードはその前に焦点の欄からキーボードを外す)・Android は戻るキー)でキーボードを閉じてから操作します。その手段で閉じられないとき、`tap` は対象の上端がキーボードの上に見えていれば、その見えている部分を押します。`type` / `clearInput` と、見えている部分の無い `tap` は、何も触らずにステップを失敗にします —— リターンキーなら閉じられますが、欄の動作も発火してしまうので自動では押しません。そうしたいときはステップの前に `pressEnter()` を呼んでください。直前のステップで欄を `tap` していれば、`type` / `clearInput` はその欄に焦点があるものとして、キーボードを閉じずに打ちます。Android では、キーボードが出ている間に対象が見つからないとき(窓がキーボードの上まで縮み、下の要素が木から消えます)、戻るキーでキーボードを閉じてもう一度だけ探します。
- キーボードが表示されているかどうかの検証は別の検証コマンドです。
  [キーボードの検証](./keyboard_assertion_ja.md)を参照してください。
- **`settle: false`** を渡すと、このコマンドの操作後の「画面が落ち着くまでの待ち」を省きます(次のステップは動いている最中の画面を見ることがあります)。詳細は [tap](./tap_ja.md) 参照。

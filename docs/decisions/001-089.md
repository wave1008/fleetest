## DR-1 失敗の記録に「環境要因」などの分類を置かない

- 種別: 方針
- 決定: ユーザー(日付未記録)
- 内容: 失敗の記録に置くのは事実(フェーズ・コマンド名・経路・注記)だけ。言えない欄は省き、「その他」に丸めない
- 理由: アプリが重いのか機械が混んでいるのかをツールは区別できず、推測は誤った緑・赤を作る
- 見直す条件: 未記録
- 参照元: CLAUDE.md「失敗の記録と操作の規律」

## DR-2 モニターの配信を止めるのは性能の計測と regress.py の回帰だけ

- 種別: 実測
- 決定: ユーザー(regress.py が自分で止めて戻すのは 2026-11-11)
- 内容: 合否を見るだけの実行では配信を止めない。regress.py は段2の前に全マシンの配信を止め、終わり・中断のどちらでも戻す
- 理由: 配信ありの回帰で、手元の Android が白紙・固まりで赤になり、止めて回し直すと同じシナリオが通った(11/1・11/11)。8台に配信を張ったフル E2E では Android が実際に落ちた
- 根拠: docs/verification/operations.md「モニターと E2E」
- 見直す条件: 配信を張ったままの回帰で、配信が原因の赤が出なくなったと測れたとき
- 参照元: CLAUDE.md「デバイス実行(E2E)」

## DR-3 特定のアプリに特化した直しを採用しない

- 種別: 方針
- 決定: ユーザー 2026-11-13
- 内容: 判定・自動の操作・待ちの条件を、1つのアプリの形(id・ラベルの語・表記・寸法)に合わせて書かない。条件は形の一般的な性質で書き、固定コーパスの全数で直しの前後を突き合わせる
- 理由: 1つのアプリの形に合わせた条件は、別の画面で誤った赤・緑になる(`*円*` を ¥ にも当てた待ち・名前だけでグラバーを引いたシートの救済は、どちらも外した)
- 見直す条件: 未記録
- 参照元: CLAUDE.md「判定の規律」

## DR-4 根拠のない定数を置かない

- 種別: 方針
- 決定: ユーザー(日付未記録)
- 内容: 定数には根拠・単位・尽きたときの発話を書く。書けないなら数字を調整せず、数字への依存を消す
- 理由: 片方の文脈で詰めた値は、別の文脈で遅くなるのではなく黙って誤る
- 根拠: MN-12.1・MN-104.5
- 見直す条件: 未記録
- 参照元: CLAUDE.md「判定の規律」

## DR-5 API の JSON 契約に後方互換の読み替えを置かない

- 種別: 方針
- 決定: ユーザー 2026-09-20
- 内容: 契約を後方非互換に変えたら版を +1 する。欄を足すときも `decodeIfPresent ?? 既定値` で古い形を吸わず、必須にする。欄が無いこと自体が意味を持つ省略可の欄(「測っていない」等)は読み替えに当たらない(DR-75)
- 理由: 互換の経路はテストでしか踏まれずに腐り、沈黙する縮退を作る(decode 失敗で機械1台ぶんの行が消える等)。リモートは毎回 align で同じ中身へ揃える運用なので、版のずれた状態は存在しない
- 見直す条件: リモートを align で揃える運用をやめるとき
- 参照元: CLAUDE.md「版と契約の同期」

## DR-27 `hideKeyboard` は閉じなければ Enter を送る

- 種別: 方針
- 決定: ユーザー(日付未記録)
- 内容: iOS の `hideKeyboard` は、何もない点のタップで閉じない(または点が無い)ときに、OS の入力補助バーの Done を押し、それでも閉じなければ Enter を送る。注記に、Enter が欄のリターンキーの動作(検索・送信・次の欄)も発火させることを書く
- 理由: `hideKeyboard` は利用者が閉じることを明示的に求めたコマンドで、iOS には Android の戻るキーに当たる副作用の無い手段が無い。人が閉じるときと同じ順(何もない所を叩く → Done → リターンキー)で最善を尽くし(DR-26)、欄の動作も発火し得ることは注記で言う。閉じることが副作用になるだけの操作では押さない(DR-28)
- 見直す条件: 未記録
- 参照元: dsl-syntax.md「キーボードの観測と `hideKeyboard`」・commands.md `hideKeyboard`(DR-28 と対)

## DR-29 `scrollFrame:` に型付きセレクタ(`Sel`)版を置かない

- 種別: 方針
- 決定: ユーザー 2026-08-04
- 内容: `scrollFrame:` 引数だけは String 固定。1対1を保証するのは対象セレクタまで。再提案しない。`SelOverloadParityTests.testScrollFrameRemainsStringOnly` が固定する
- 理由: `scrollTo` は対象と `scrollFrame` の両方を取るのでオーバーロードが 2×2 になり、他20コマンドと合わせて語彙が増える。一方 `scrollFrame` は生成コードにほとんど出ない(生成側は文字列版を出す既定)ので、「型付き経路を選ぶと機能が減る」実害が最も小さい
